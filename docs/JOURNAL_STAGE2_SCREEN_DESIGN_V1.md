## 画面構成（両デザイン共通）
**PC**：左に日次予定と件数、右にToDoと業務メモ。左の常設ナビと右のページインデックスから「今日 / 週間 / ToDo / タスク / 予定 / 業務メモ」に切替。情報密度が高い業務にも耐える一覧・編集導線を持つ。

**スマートフォン**：PC見開きを縮小するのではなく、幅約384pxの単ページ表示。「今日」は日付と件数の下に、ToDo→予定→業務メモの順で配置。画面下部のナビを固定し、「今日 / 週間 / ToDo / タスク / その他」から移動。「その他」に予定・業務メモを含む。重要なToDoが画面下へ埋もれない優先順位。

## トーン
- Linen: 生成りの用紙、細い罫線、スモークブルーのアクセント、落ち着いた余白、角丸を控える。装飾は視認性を妨げない。
- Margin: セージ、テラコッタ、くすみ藤色、控えめな紙テープ・付箋、柔らかな丸み。同じ情報密度と業務機能を保ち、幼くならない。

## 操作デモ
- テーマ切替、PC/スマホ切替、ページナビ、カレンダーの日付、ToDoチェックの仮表示、モックダイアログ。
- 保存先を持たない表示のみ。タスク/予定/メモの実編集、通知、検索、権限、競合制御などは**実装していない**。
- プロトタイプ上の件数・内容は架空のサンプル値。日時表示は2026-11-05を基準とする。

## 画面確認結果
- Chromiumの実描画で2デザイン×2端末の計4画面を確認。
- 表示/端末切替、今日→タスク→業務メモのページ移動、ToDoの仮完了、ダイアログの開閉を自動操作して成功。
- モバイルのコンテンツ横方向はみ出しなし。JS構文と実行時エラーを確認。
- **現行業務機能の回帰テストではない**。次工程でcanonical handlerを接続した時点で別途確認が必要。

## 第3工程の接続条件
1. 最新mainを再取得してModern/Paletteの最新変更、リリース定義、責務台帳を再確認。
2. 既存の表示モード選択UIにJOURNALを統合。並行する重複セレクタを実装しない。
3. JOURNAL専用のレイアウト/コンポーネントを追加しつつ、ClassicのFirebase購読、追加/編集/削除、繰り返し、通知、メモ、ToDo、競合制御を正本として呼び出す。
4. Linen/Marginは同じ機能コンポーネントのテーマ差分。意味色は固定、装飾トークンは切替。必要に応じ暗色対応は別途丁寧に設計。
5. PC/スマホ/大量件数/長文/空状態/オフライン/操作失敗時を確認し、既存回帰を通過してからmainへ反映。
6. 当面、現行Classic/Modern/Paletteの見た目や保存仕様を不用意に変更しない。
