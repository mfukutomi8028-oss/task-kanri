# 業務管理ボード：Firebaseバックアップ／復元手順（2026-11-06）

## この文書の位置づけ

運用環境は GitHub Pages の公開サイトと Firebase Realtime Database のデータ保存を使用する。**GitHubのソース履歴だけではFirebaseの業務データを復元できない。** この文書はバックアップ取得前の確認と、データを外部に漏らさないための手順を示す。ここに記しただけではバックアップは取得されない。

## 原則

1. 公開リポジトリ `task-kanri`、PR、Issue、GitHub Actionsのログや成果物、チャットへ**平文の業務データや認証情報を置かない**。ファイルパターンを `.gitignore` に追加しているが、これは誤操作の軽減であり情報漏えい防止の保証ではない。
2. 保存先は病院が管理・承認したアクセス制限付きの媒体や保管領域を第一候補とする。院内PCに保存する場合は端末故障への備えとして、**別媒体に暗号化済みのコピー**を確保する。
3. GitHub Freeは非公開リポジトリを作成できるが、Gitリポジトリは専用バックアップサービスではない。利用するなら病院の許可を得た非公開の補助保管場所とし、**暗号化済みの小容量アーカイブのみ**を扱う。個人アカウントへの業務データ保存は病院の方針と退職時の引き継ぎを確認する。
4. バックアップに用いる暗号化パスワード・回復鍵は、バックアップファイルと同じ場所へ置かず、組織の定めた安全な手段で保管する。
5. 患者情報・要配慮個人情報・資格情報はこのアプリへ入力しない。既存のFirebase Rulesは認証を強制していない可能性がある。本番ルールの設定確認、権限制御、データ移行は別工程で進める。

## 最初の手動バックアップ（読み取りのみ）

1. Firebase管理者が、対象プロジェクトとRealt​ime Databaseインスタンス、使用中のルーム識別子を確認する。アプリの公開URLだけで対象を決めず、**本番インスタンスであることを確認**する。
2. Firebase Console → **Realtime Database → Data** のツリーから、対象ルームを含む `rooms` ノード（すべてのルームを保全する場合）または必要なルームノードを選択する。
3. 右のメニューから **Export JSON** を選択する。エクスポートは選択した子ノードも含む。ダウンロードしたデータは `YYYYMMDD-HHMM-rooms.rtdb.json` 等に名前を付け、**公開Git作業フォルダ外の保護された一時保管先**へ移動する。
4. 同時にRealtime Databaseの**Rules**画面から、当時適用されているルールを別途保存する（データのJSON出力だけでルールの復元までできると仮定しない）。
5. 取得日時（日本時間）・Firebaseのインスタンス名・対象ノード・JSONのファイルサイズ・SHA-256を、データ本文を含まない管理台帳に記録する。Windows PowerShellの場合：
   `Get-FileHash -Algorithm SHA256 -Path "C:\\保管先\\20261106-1000-rooms.rtdb.json"`
6. JSONの読込可能性、対象ノードとデータ件数などの整合を確認後、組織承認済みの方法で暗号化する。**平文の一時ファイルは不要になった時点で安全に処分**する。
7. 独立した保管先へ暗号化済みコピーを置き、ファイルの読取・復号ができることを確認する。データ復元は必ず隔離環境で先に実施する。**本番ノードにいきなりImport JSONを実行しない**。

### 仮の世代管理案

- 日次7世代、週次4世代、月次3世代を目安にする。実際の世代数は容量・重要度・運用担当者と決める。
- 月1回以上の読み取りと復号検証、四半期ごとの隔離環境での復元演習を推奨する。これは提案値であり、現時点で自動実行されない。
- エクスポートが大きい場合や毎日自動化が必要になった場合は、Firebaseの**Blazeプランの自動バックアップ（Cloud Storage）**を検討する。ストレージ料金と保存期限に注意する。

## 復旧時に必要なこと

- 復旧先は本番と異なるFirebaseプロジェクト／エミュレータを使用する。
- ダウンロードJSONに含まれるノードと、復元先で選択するノードを一致させる。Import JSONは既存データを書き換えるため、差分・衝突・業務停止時間を確認したうえで承認後に実行する。
- データだけでなく、適用時点のRules、アプリのGitコミットSHA、構成情報、必要に応じて依存するFirebaseサービスを併せて復元する。
- バックアップ日時以降の変更は原則として別途回復方針が必要。バックアップ自体が完全であった証拠として件数・ハッシュ・復元検証記録を残す。

## GitHub Freeの利用条件（確認日：2026-11-06）

- Freeでも非公開リポジトリは作成可能。ただし、公開`task-kanri`に業務バックアップは置かない。
- Actions成果物には無料枠（500MB）と保持期間（既定90日）があり、単独の長期バックアップ先にしない。
- Git履歴は差分が残り続けるため、大容量の定期JSONダンプをリポジトリへコミットし続けない。
- **現段階では実際のバックアップ、クラウド側のアクセス設定変更、自動定期実行、暗号化鍵の作成・設置は行っていない。**
