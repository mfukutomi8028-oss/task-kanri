## 成果物

業務管理ボードの既存機能に対応する独立した「手帳型画面」をLinen / Marginの2種類でデザイン。

- Linen PC：見開き。紺色の装丁、生成りの紙、細い罫線、余白を活かした落ち着いたビジネス手帳
- Margin PC：見開き。緑色の装丁、付箋風見出し、さりげない色のインデックス
- Linen / Margin モバイル：見開き縮小ではなく、1ページ、日付操作、固定下部ナビ、クイック追加
- モバイルToDoの表示案も両デザインで制作
- PC / モバイルの比較画像2枚、個別画面PNG6枚、自己完結HTMLデザインプレビューを生成（対話内の成果物として納品）

同一の情報構造と操作をLinen / Marginで共通化し、テーマで意味色を変えない。

## 画面構造

PC：左装丁のインデックス「今日 / 週間 / ToDo / タスク / 予定 / 業務メモ」。今日画面の左ページに「日付、今日の予定、未完了・期限超過サマリ、業務メモ」、右ページに「ToDo、タスク進捗、お知らせ」。

モバイル：表示は1ページずつ。下部固定ナビ「今日 / 週間 / ToDo / タスク / メニュー」。メニュー内に「予定 / 業務メモ / Linen・Margin切替」。上部・下部でメニューを重複させず、今日・週間・予定では日付を選択。ボタン類は原則44px程度の操作領域を確保。

6画面（今日、週間、ToDo、タスク、予定、業務メモ）の画面イメージを切替可能なデモを用意した。

## 技術的な前提

- 本工程は **デザイン制作のみ**。既存のアプリHTML / CSS / JavaScript / Firebaseには未接続。
- HTMLプレビューのToDoチェック・追加・画面切替はローカルの架空データのみを操作。本番データのCRUD、通知、同期、競合制御は実装していない。
- 第3工程では既存Classic DOMと業務ロジックを正本とし、display selectorとテーマ選択の責務を現行実装へ統合する。新規Firebase client、二重保存経路、重複切替実装は禁止。
- Modern/Paletteを別チャットで並行開発中。統合前に最新mainを再取得し、既存選択肢とCSSを侵食しないよう調整する。
- 患者情報・要配慮個人情報など機密情報の入力を許可する設計ではない。現行READMEの安全境界に従う。

## 表示検証結果

2026-11-05：Chromiumで幅320/360/390/768/1024/1280/1536px × 2テーマ × 6ページ、計**84組み合わせ**をレンダリング確認。JavaScript実行エラー・横方向のはみ出しなし。スマートフォンでメニュー開閉、テーマ切替、ToDoの状態変更、画面遷移を確認した。

ただし、これはデザイン用HTMLプレビューの検証であり、実運用の保存・通知機能の回帰テストではない。
