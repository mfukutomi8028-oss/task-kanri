# 手帳ワークベンチ型 UI/UX 実装設計 v1.0

日付：2026-11-03 / 対象：業務管理ボード Ver.328（Classicへ復帰済み）

**本書はD案の実装設計。新UIはまだ実装しない。** 過去のModernを再利用せず、Classicの業務機能・保存処理を基盤として新規設計する。

## 1. 目標と基本方針

- デジタル手帳のような温かくかわいい質感。紙の見開き、インデックス、細い罫線、柔らかい配色。
- 「今日何をするか」「次に何を確認するか」「関連する資料は何か」が同じ視線の流れで分かる。
- 装飾的な巨大カードや無用な説明を増やさず、大量件数でもスクロール量を抑える。
- Classicのタスク、個人ToDo、予定、業務メモ、コメント、履歴、通知、共有・競合機能を維持。
- **画面は新しく、業務データの正本とFirebase保存処理は一本化**。D案独自の購読・保存ロジックを複製しない。

## 2. 情報設計（ナビゲーション）

| 主な入口 | 役割 | 対応する既存機能 |
| --- | --- | --- |
| 今日の手帳 | 今日の予定、期限超過、次にやること、直近の情報 | 今日、予定、タスク、個人ToDo、通知 |
| ToDo | 自分の未完了、今日完了したもの、履歴 | 個人ToDoの追加・完了・編集・並び替え |
| タスク | 共有タスクの一覧、ボード、期限別、検索、一括操作 | 共有タスク、分類、状態、担当、コメント、履歴 |
| 予定 | 今日・週・月、作成・編集、繰り返し、日付コピー | 既存スケジュールとタスク関連付け |
| ノート | 業務メモの分類・検索・固定・編集・タスク化 | 既存業務メモ |

「今週」は今日の手帳内の表示切替とし、独立した第6の業務データを作らない。グローバル「＋」でタスク・ToDo・予定・業務メモの種類を明示して追加する。

## 3. PCの基本構成：見開き手帳

### 今日の手帳（初期画面）

~~~text
┌ 業務管理ボード   [検索]     [＋追加]    [通知]   [利用者・ルーム] ┐
│ [今日の手帳] [ToDo] [タスク] [予定] [ノート]                 │
├──────────────────────────────────────────────────────────────┤
│ 11月3日 火曜        [前日] [今日] [翌日]   [今週を見る]      │
├─────────────────────────┬────────────────────────────────────┤
│ 左ページ：進めること      │ 右ページ：文脈と記録               │
│                         │                                    │
│ 時間順の予定              │ 選択中：情報システム定例会議       │
│ 09:00  定例会議          │ 状態 / 担当 / 期限 / 関連タスク   │
│ 11:00  PC入替確認        │ [編集] [タスクを開く]             │
│ 14:00  機器納品          │ ─────────────────────────          │
│ [全12件を見る]           │ 関連するメモ・手順・参考URL       │
│                         │ ・事前に確認すること               │
│ 次にやること              │ ・会議前に見ておく情報             │
│ □ PC設定確認      今日   │ [メモを開く] [タスクにする]       │
│ □ 部署へ連絡      明日   │                                    │
│ □ 発注確認        超過   │ コメント・履歴（折りたたみ）      │
│ [全26件を見る]           │                                    │
└─────────────────────────┴────────────────────────────────────┘
~~~

**動作原則**
1. 左ページの行を選ぶと右ページに内容を表示。画面を行ったり来たりしなくてよい。
2. 予定・ToDo・タスクは初期表示各4〜8行まで。件数と「すべて見る」を表示し、データ件数に比例してホームが無限に伸びない。
3. 共有タスクと個人ToDoは同じ「次にやること」欄へ並べても、種類・操作・更新対象を混同しない。
4. 詳細編集・保存はClassicの既存フォームと競合制御を再利用。別タスクへ移るときは未保存入力を保護。
5. 右ページは常に選択中の1件だけに集中。関連情報は折りたたみ、長い履歴やコメントを初期表示で全展開しない。

### 今週の手帳

左ページに月〜日の7日ストリップ（予定/期限件数の抜粋）、右ページに選択日の詳細と確認事項。週ごとに独立したデータを複製せず、既存予定・タスク・ToDoから計算する。

### タスクのページ

初期は表形式。列：名称／状態／担当／期限／優先度。選択すると右ページにタスク詳細。上部に検索とフィルタ（状態、分類、担当、期限）。ボード・タイムラインは既存の表示切替を残す。

大量件数でも行高48〜56px程度。複数選択は選択時のみ一括操作バーを表示し、対象件数と実行操作を明示する。関連予定・ナレッジのある削除は既存の競合・整合性判定を必須とする。

### ノートのページ

左ページ：メモの見出し、カテゴリ、ピン、検索、更新日。右ページ：本文・コピー・編集・「このメモからタスク作成」。初期段階で保存するのは既存業務メモの正本。

カテゴリは既存の「定型情報」「宛先・連絡先」「手順」「URL・リンク」「その他」。会議ノートという専用データ形式と、メモ・タスクの永続的な相互リンクは後工程で検討する。

## 4. PC・タブレット・スマホの表示

| 幅 | レイアウト |
| --- | --- |
| 1200px以上 | 左右見開き。左：予定/行動、右：詳細/メモ |
| 768〜1199px | 左主体、選択すると右詳細をドロワー表示 |
| 767px以下 | 1ページ。上部で「今日・やること・ノート」の内容を切替。主要ナビは下部 |

320px/390pxでも横スクロールを許さない。ソフトキーボード表示時に下部ナビが入力欄を覆わない。操作領域は原則44px以上。Tab/Enter/Escで主要操作が可能。

## 5. ビジュアル定義（D案を維持）

| 要素 | 色・基準 |
| --- | --- |
| アプリ外側の背景 | #F2F5F8 |
| 紙のページ | #FFFDF8 |
| 本文 | #25374B |
| 補助文字 | #54677C |
| 主要操作・リンク | #425B8D |
| ラベンダーの選択面 | #EDF0FB |

| 期限超過 | #9B522D |

本文は原則16px、補助14px、見出し20〜24px。紙風の角丸・インデックス・細い罫・小さなアイコンでかわいさを表現。濃淡だけで状態を示さず文字も併記。本文はWCAG AA相当の4.5:1以上を目標とする。派手なアニメーション、巨大なパステルカード、余白だけで見せるHP的レイアウトは禁止。

## 6. 既存Classic機能との接続表

| 機能 | D案での操作 | 既存処理の再利用 |
| --- | --- | --- |
| 今日の状況、期限超過 | 左ページの要約 | 現行タスク/予定/ToDo集計 |
| 個人ToDo | チェック・詳細・追加・完了履歴 | 現行ToDoの作成・編集・完了・履歴 |
| 共有タスク | 選択・詳細・一括変更・完了メモ | 現行タスク作成/編集、単一書込、CAS |
| 予定 | 時刻欄・日/週/月・繰り返し・コピー | 現行スケジュールの保存・通知 |
| 予定と関連するタスク | 右詳細の関連タスク欄 | 既存関連タスクID |
| 業務メモ | ノート欄、検索、タグ、固定、編集 | 現行業務メモ処理 |
| 業務メモ→タスク | ノートの「タスクにする」 | 既存 createTaskFromMemo |
| コメント、返信、リアクション | 右詳細の展開パネル | 既存タスク/ワークフロー |
| お知らせ、個人通知 | ヘッダー、今日の要確認欄 | 既存通知/履歴 |
| 競合・保存失敗 | 明確なエラーと再読込・差分確認 | 既存revision照合・Firebase処理 |

「予定とタスク」は既存の関連付けを表示する。**メモとタスクの永続的な双方向リンクは既存にあると仮定しない**。「メモからタスク起票」は既存機能だが、起票後のリンク関係を新仕様として設計する場合は別途追加する。

## 7. 追加機能と範囲

### 初期リリース（データスキーマを変更しない）

- 今日/今週の仮想ページと右詳細
- 既存のタスク・ToDo・予定・業務メモへの一元的な入口
- 既存メモからのタスク化
- 表示件数上限、全件一覧への移動、フィルタ・選択の維持
- 端末内の軽量な表示設定

### 次工程で別設計する新機能

- 日次ページ専用の自由記入メモ
- 会議ノート：議題・決定事項・次の確認日・関連タスク
- フォロー待ち：相手・依頼日・確認予定日・対応結果
- 案件ノート・複数種類間の明示リンク

新規のデータ形式や権限チェックが必要となるため、初期リリースへ無条件には混ぜない。タスクやメモのデータを別場所に丸ごとコピーしない。

## 8. 実装構成と移行

- Classicの app.js / work-features-v167.js および関連workspace-*が**唯一の保存処理の正本**。
- 新しいD表示レイヤーは別フォルダ（候補：planner/）へ新規実装する。旧Modernを再導入しない。
- 新UI用には表示用の読み取りアダプターとClassicへのコマンド委譲を限定公開する。Firebase SDKの購読・トランザクションを新UIに追加しない。
- Classicのダイアログ・保存経路を1つに維持し、重複した旧UIコードを最終移行時に整理する。
- 新UIの承認前はClassicを稼働させ続ける。データ移行不要でClassicへ戻せることが必須。
- 開発候補：book-shell.css、book-tokens.css、book-today.js、book-list.js、book-notes.js、book-adapter.js（いずれもまだ存在しない）。

## 9. 受入基準（操作）

1. 朝：今日の予定、期限超過、ToDoから次にすることが見える。
2. 会議予定を選択→右ページに関連タスクとメモが表示される（ない場合は空状態を明示）。
3. ToDoを完了→完了履歴が記録され、他利用者の項目は変わらない。
4. メモからタスク作成→既存Classicフォームで内容を確認して保存。
5. 同じタスクを2端末で編集→古い更新番号の保存は拒否する。
6. タスク100件でも今日ページに100件並べず、一覧/検索へ到達できる。
7. PC・スマホ・200%相当拡大で操作不能な重なりや横スクロールがない。
8. 保存成功・保存失敗・同期確認中を区別し、未保存の入力を勝手に破棄しない。

## 10. 実装順序

1. **第0工程：完了** Modernを撤去し、Classicのみへ戻す（Ver.328）。
2. **第1工程：デザイン承認** 今日・タスク・ノート・スマートフォンの4画面モックを作成。密度/見た目/動線を評価。
3. **第2工程：閲覧接続** 「今日の手帳」を既存Classic正本で表示し、件数・期限・選択詳細を一致させる。
4. **第3工程：操作接続** 作成・編集・完了・一括操作・通知・メモからのタスク起票を既存処理へ接続。
5. **第4工程：正式導入** 全体の機能差分、スマホ、保存競合を確認して本番化。古い表示実装を整理する。
6. **第5工程：追加価値** 会議ノート、日次メモ、フォロー待ち等を個別のスキーマ・権限・更新番号設計に基づいて検討。

## 11. セキュリティ上の制約

現行Firebase Rulesは適切なアクセス制御を保証していない。画面設計の完成は、機密情報を保存できることを意味しない。患者情報、医療記録、パスワード、要配慮個人情報を入力しない。正式な医療機関運用で扱う場合はFirebase Authentication、ルーム単位の最小権限、監査、バックアップ・復元の検討が先決。

---

**採用方針：** D案の見た目は「かわいい手帳」、使い方は「業務を前に進める道具」。旧Modernの見づらさ（大きな部品、長いスクロール、重複する操作）を持ち込まない。
