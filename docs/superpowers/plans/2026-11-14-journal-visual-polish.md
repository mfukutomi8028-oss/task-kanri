# JOURNAL実画面監査：空状態・タブレット・予定の時刻指定（2026-11-14）

## 根拠
JOURNAL Ver.595を外部通信遮断のローカル合成画面で、1366/768/390/320pxそれぞれ「今日・タスク・予定」をPlaywright描画し、PNGと矩形の実測値で監査した。実データ・本番Firebaseは利用しない。

## 目標
「手帳の素朴さ」は残し、空の紙面と重い装飾を抑えて操作する情報を手前に置く。記録の保存経路、ほかの画面モード、既存の高度な予定時刻指定は変えない。

## 発見
- 1366pxタスク：タスク0件でも案件索引の背に合わせ作業机が約890pxまで伸び、空白が大きい。
- 768pxタスク：案件索引が展開されたまま最初の画面の大半を占有し、作業机までスクロールが必要。
- 320/390pxタスク：件数4個のうち最後だけが次の行に回ってしまう。
- スマホ予定：日別に「空き時間から追加 1枠」が繰り返され、日付と予定を見る目線を妨げる。
- PC案件アトリエ：囲み線がほかの紙面に比べ重く、主要操作の高さが44px未満の例がある。

## 選択肢と判断
- **採用**：既存のDOMと操作を維持し、索引の初期開閉と空状態のレイアウト、件数グリッド、予定の補助導線を局所改善。見た目と挙動の両方を小さく修正できる。
- 棄却：画面ごとに新しいタブや別のタスク一覧を追加。既存の復帰・保存・選択の責務と衝突しやすい。
- 棄却：予定の高度な時刻指定機能を削除。既存テストとユーザーの高度な時間指定ニーズを損なう。目立たない補助操作へ格下げする。

## 受け入れ条件
1. 768pxタスクの索引は最初折りたたみ、同じボタンで展開・フィルタ操作可能。データ保持とフォーカス復元を維持。
2. 320/390px件数4個を2x2で均等に表示し、幅はみ出しなし。
3. 1366pxタスク0件時は索引をたたみ、作業机の空状態を短く。タスク存在時は通常の索引・作業机・進行ログを維持。
4. スマホの予定時刻補助は「時間指定」という補助リンクに整理し、既存の空き枠選択・開始時刻指定・保存を維持。
5. 既存Protocol、ブラウザ回帰に加え実スクリーンショットを再検証。必要な場合のみ配信Ver.596を作る。
