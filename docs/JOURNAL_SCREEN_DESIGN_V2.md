## 1. 今回の成果
デスクトップ見開き（1600px幅）・スマートフォン単列（430px幅）を、以下のテーマごとに4画面制作した。ブラウザで操作できる単一HTMLプロトタイプも用意した。これらのPNG/HTMLは会話内のダウンロード成果物として提供し、GitHubへは設計仕様を保存する。

| 対象 | Linen | Margin |
|---|---|---|
| Desktop | ネイビーの表紙＋アイボリー＋細い罫線 | セージの表紙＋淡色タブ＋付箋 |
| Mobile | 単列の予定→指標→ToDo→タスク→メモ | 同じ情報設計に、彩色したインデックス・付箋 |
| 共通機能 | 今日、週間、ToDo、タスク、予定、業務メモ | 同左 |

### HTMLの試作範囲
- Linen / Margin ボタンによるデザイン切替
- 「今日」「週間」「ToDo」「タスク」「予定」「業務メモ」のデモページ切替
- ToDoチェックのローカル視覚反映（デモのみ）
- モバイル下部ナビと「メニュー」→予定/業務メモ
- 検索・新規追加・通知は案内ダイアログのみ（Firebaseや業務データの保存はしない）

## 2. 共通情報配置

### PC（見開き）
- 外枠：表紙をイメージした外周、ページタブ、中央の綴じ目、紙面2ページ
- 左側：日付・今日の予定タイムライン・日付選択・件数サマリ・期限超過警告
- 右側：ToDo・進行中のタスク・業務メモ
- サイド：今日、週間、ToDo、タスク、予定、業務メモのインデックス
- 上部：検索、通知、新規追加、デザイン切替
- パソコンの余白を情報密度と読みやすさに活用し、装飾でクリック範囲を塞がない

### スマートフォン（単列）
- 上部：JOURNAL見出し、デザイン切替、検索・追加導線
- 本文：日付＋1週間のコンパクト日付帯、予定タイムライン、未完了・期限超過の指標、ToDo、タスク、業務メモ
- 下部：今日、週間、ToDo、タスク、メニュー
- メニュー：予定、業務メモへ遷移
- 画面幅に縮小した見開きを押し込まない
- 一覧量が増えた場合はページを分け、詳細のスクロール位置を維持する設計

## 3. デザイン差分

### Linen
- 背景 #EEECE7 / 紙 #FFFEFA / 墨 #202D36 / アクセント #315F70 / 表紙 #465764
- 品質基準：控えめな表紙の立体感と紙の余白、細い罫線、整った文字組み
- 大人向けの静かな雰囲気。意味のないポップ装飾を極力避ける

### Margin
- 背景 #EDEFE8 / 紙 #FFFDF7 / 墨 #273A37 / アクセント #38735D / 表紙 #718F7B
- 装飾：淡い複数色のタブ、付箋と紙テープ、控えめな小さな装飾
- 「かわいすぎない」「業務に使いやすい」を優先
- 警告の赤/重要状態の色はテーマ色と別に管理

## 4. UIルール・見落とし対策
1. ToDo完了・予定編集・タスク詳細・業務メモ編集等の**本番処理は既存ownerを唯一の正本**にする。デモHTMLのイベントは実装にコピーしない。
2. Classic / Modern / Palette / Journalは表示モードとして1か所で管理する。実装時はその時点の最新mainのselectorを確認し、二重のモード選択処理を導入しない。
3. 文字は本文を基準に十分な大きさを確保し、補助テキストを極小化しない。背景色だけに依存しない期限・状態の識別。
4. 長い件名、0件、大量件数、期限超過、権限/接続状態、タッチ操作、キーボード操作、ダークテーマ未実装状態を確認する。
5. モバイルの「メニュー」は予定/業務メモへの導線であり、単に業務メモへ遷移してはならない。
6. タブとページめくりアニメーションは装飾効果。機能に必須のジェスチャーにはしない。
7. 本画面の作成では実際の患者情報や業務上の機密情報を使用しない。リポジトリのセキュリティ注意事項を維持する。

## 5. プロトタイプの動作確認（2026-11-05）
- Chromium / Playwrightで4種類の描画ができ、ページのJavaScriptエラーは0件。
- デスクトップ幅1600px: 「タスク」切替とLinen→Margin切替成功、横溢れなし。
- スマートフォン幅390px: 「週間」切替→メニュー開閉→「予定」切替成功、Linen→Margin切替成功、横溢れなし。
- 画像サイズはPC 1600×1089、スマートフォン430×1627または1631（全ページ撮影）。
- これは**デザインモックの動作確認**であり、Firebase接続・実データ保存・本番CIの合格を意味しない。

## 6. 第3工程で必要なこと

## 結論
JOURNALは**LinenとMarginを別アプリにしない**。同じ画面構造・機能に別のスタイリングを与え、業務データは既存の保存正本から取得する。デザインだけで本番画面を置き換えたり、旧業務処理と新業務処理を併存させない。
