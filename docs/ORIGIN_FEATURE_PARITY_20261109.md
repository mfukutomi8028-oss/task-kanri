# Origin: Classic機能の専用UIへの移行

基点: `83cfbeaa85279473aefaf7ca8cd994c95debb93d`（PR #767）。
OriginはShadow DOM内で表示し、既存の業務処理・競合制御・保存先を再利用する。
ClassicのDOMを流用せず、Firebaseの保存形式も変更しない。

## 今回移行した操作

| 対象 | Originの導線 | 共通の処理 |
| --- | --- | --- |
| 予定の複数日・繰り返し登録 | 新規予定 → 繰り返し・複数日登録 → 作成日を確認 → 登録 | schedule.preview-batch / schedule.batch |
| 予定の複製 | 予定詳細 → 複製して作成 → 内容と日時を編集 → 登録 | schedule.create |
| タスクの複製 | タスク詳細 → 複製して作成 | duplicateTask。独立した繰り返し系列、revision初期化等の既存仕様を維持 |
| コメントの閲覧・追加 | タスク詳細 → 対応履歴・コメント | readCommentTask / addComment |
| お気に入り登録・絞り込み | タスク詳細 → お気に入り／タスク一覧 → お気に入り | task.star |
| ToDo並び替え | ToDo詳細 → 上へ移動／下へ移動 | todo.move |
| メモのタグ編集 | メモ編集 → タグ | memo.create / memo.update |
| 前提タスクの追加・解除 | タスク詳細 → 前提・関連タスク・確認リマインダー | WorkBoardWorkflowV152.writeDependencies |
| 関連タスクの追加・解除・詳細移動 | 同上 | writeRelations / Origin既存の関連詳細往復 |
| 個人リマインダーの保存・解除 | 同上。今日画面でも対象日の終了までの未完了分を表示 | writeReminder / remindersFor |

予定の登録方法は毎日、平日、曜日指定、毎月指定日、第N曜日、月末、最終平日、毎年、個別日付。
作成日計算、上限200件、時間重複、大量登録確認は既存の共通処理が担当する。
入力変更後はプレビューを無効化し、未確認の条件では一括登録しない。

コメントとタスク複製の公開アダプターは所有者・更新番号を確認して既存処理へ委譲する。
コメント・個人設定の入力中に詳細を閉じる場合は破棄確認を行う。
前提タスクの完了制限はOriginの完了・編集保存・一括完了の各経路でも確認する。

メモタイトル80文字・本文必須かつ6,000文字以内に入力欄を合わせた。
以前のOriginタイトル上限150文字・本文任意は共通保存処理と不一致だった。

## 継続対象（全機能移行の完了を意味しない）

以下は引き続き専用UIへの移行・機能差確認が必要。

- タスクの繰り返し条件の作成・変更、開始日・予約、テンプレート。
- 既存の予定系列の範囲指定編集・削除。現時点ではClassicの詳細設定導線を維持。
- コメント返信・リアクション・メンションの専用操作。
- 受信箱・アーカイブ・ナレッジ・重複統合・統計・保存ビュー。
- 分類・状態・利用者等の管理操作、およびボード・タイムライン等の表示方式。

これらを無効化・削除したわけではない。既存Classicの機能を維持している。
新しい保存処理を複製せず、それぞれの現行API・所有者・競合制御を調査してから移行する。

## 検証

`tests/origin-feature-parity.spec.mjs` は次を実操作で確認する。

- 320 / 390 / 1366pxでの複数日プレビュー・変更後の再確認・保存・横幅。
- コメント保存、競合時の入力保持、未保存入力の破棄確認。
- 予定複製、メモタグ、お気に入り、ToDo並び替え。
- 390pxでの前提・関連・リマインダー共通データ反映、完了制限、入力保持。

既存キーボード検査では「完了ボタンが最後」と決めつけず、追加操作を含む最後の有効ボタンからのフォーカス循環を確認する。
Protocol、Origin回帰、PRの認可・Firebaseを含む既存CIを公開判定に使用する。
