# Origin: Classic機能の専用UIへの移行

基点: `83cfbeaa85279473aefaf7ca8cd994c95debb93d`（PR #767）。
OriginはShadow DOM内で表示し、既存の業務処理・競合制御・保存先を再利用する。
ClassicのDOMを流用せず、Firebaseの保存形式も変更しない。

## 今回移行した操作

| 対象 | Originの導線 | 共通の処理 |
| --- | --- | --- |
| 予定の複数日・繰り返し登録 | 新規予定 → 繰り返し・複数日登録 → 作成日を確認 → 登録 | schedule.preview-batch / schedule.batch |
| 予定の複製 | 予定詳細 → 複製して作成 → 内容と日時を編集 → 登録 | schedule.create |
| タスクの複製 | タスク詳細 → 複製して作成 | duplicateTask。独立した繰り返し系列、revision初期化等の既存仕様を維持 |
| コメントの閲覧・追加 | タスク詳細 → 対応履歴・コメント | readCommentTask / addComment |
| お気に入り登録・絞り込み | タスク詳細 → お気に入り／タスク一覧 → お気に入り | task.star |
| ToDo並び替え | ToDo詳細 → 上へ移動／下へ移動 | todo.move |
| メモのタグ編集 | メモ編集 → タグ | memo.create / memo.update |
| 前提タスクの追加・解除 | タスク詳細 → 前提・関連タスク・確認リマインダー | WorkBoardWorkflowV152.writeDependencies |
| 関連タスクの追加・解除・詳細移動 | 同上 | writeRelations / Origin既存の関連詳細往復 |
| 個人リマインダーの保存・解除 | 同上。今日画面でも対象日の終了までの未完了分を表示 | writeReminder / remindersFor |

予定の登録方法は毎日、平日、曜日指定、毎月指定日、第N曜日、月末、最終平日、毎年、個別日付。
作成日計算、上限200件、時間重複、大量登録確認は既存の共通処理が担当する。
入力変更後はプレビューを無効化し、未確認の条件では一括登録しない。

コメントとタスク複製の公開アダプターは所有者・更新番号を確認して既存処理へ委譲する。
コメント・個人設定の入力中に詳細を閉じる場合は破棄確認を行う。
前提タスクの完了制限はOriginの完了・編集保存・一括完了の各経路でも確認する。

メモタイトル80文字・本文必須かつ6,000文字以内に入力欄を合わせた。
以前のOriginタイトル上限150文字・本文任意は共通保存処理と不一致だった。

## 高度な機能の追加

| 対象 | Originの導線・対応範囲 | 共通処理・制約 |
| --- | --- | --- |
| タスクの繰り返し | タスク編集 → 繰り返し。日付プレビュー、件数・終了日・無期限 | 既存の生成処理を共有。終了条件だけの変更では系列ID・作成済み件数を維持 |
| 開始日・予約タスク | タスク編集 → 開始日、タスク → 予約 | WorkBoardOriginStartBridge → persistStartDate。開始日が期限日を超える入力を拒否 |
| テンプレート | その他 → テンプレート。作成・編集・削除、タスクに適用 | canonical taskTemplates、meta revision。最後の削除で既定テンプレートに戻るClassic仕様を維持 |
| 系列の範囲指定削除 | タスク・予定編集 → 削除 → この1件／この回以降／系列全体 | captureRecurringDelete / commitRecurringDelete。件数プレビュー・系列全体の競合指紋を使用 |
| コメント返信・メンション | コメントの返信、宛先選択による @名前 の挿入 | 既存addComment / saveRemoteReply、親コメントIDを保持 |
| コメントリアクション | タスク詳細 → 各コメント | 既存toggleReaction。共同編集接続時のみ利用可 |
| 受信箱 | その他 → 受信箱。タスク移動・既読／未読・すべて既読 | 既存workflowの利用者別inbox |
| アーカイブ | 完了タスク詳細 → アーカイブ、その他 → アーカイブ → 復元 | 既存workflowのarchive設定・競合確認 |
| ナレッジ | タスク詳細 → ナレッジとして残す、その他 → ナレッジ | タスクとのリンクを含む既存atomic writer。編集・削除も既存保存処理 |
| 重複タスク統合 | タスク詳細 → 前提・関連等 → 重複タスクの統合 | WorkBoardDuplicateV182.mergeDuplicate。共同編集接続時のみ利用可 |
| 集計 | その他 → 集計 | 担当者別の未完了・完了・期限超過。予約・アーカイブを含む全タスクを集計 |
| 表示方法・保存 | タスク → 一覧／ボード／タイムライン、表示方法と並び順を保存 | 同じタスク行・操作を共有。workflow.savedViewsの既存スキーマ、利用者別保存 |
| 分類・状態・利用者管理 | その他 → 管理。追加・削除・並び替え、分類・状態の名称変更 | 既存管理関数を再利用。保護された状態の削除・完了状態の改名を拒否 |

開始日保存はタスク本体と既存の別メタデータを順に保存する。後者だけ失敗した場合は
本体保存済みであることを表示し、フォームに作成済みID・revisionを保持する。
再保存は同じタスクへの更新となり、二重作成を防ぐ。

Classicへの旧予定編集切替アダプターとOrigin内の旧切替導線は撤去した。
既存系列の各回の編集・範囲指定削除はOrigin内で行う。
系列全体の日時一括変更やボードのドラッグ操作は今回追加していない。
「高度な機能を追加した」ことと、Classicの全操作を完全に同じ粒度で移行したことは区別する。

## 更新を妨げていた既存箇所の修正

- mainの既存コメント修正（PR #769）を取り込み、確定データの描画契約を維持。
- JOURNALの検索解除を既存の共通検索所有者へ通知し、古い検索語の復活を防止。
- JOURNALの直接編集終了時は元のノートへ復帰し、詳細パネルを残さない。
- JOURNALの机上ノートのPC配置先、二重クリックと再描画の競合、追従ナビのoverflow祖先を修正。
- ブラウザ検査の日本時刻、保存後の詳細閉鎖、RAF完了待ち、文言正規化を現行仕様へ整合。

## 検証

`tests/origin-feature-parity.spec.mjs` は次を実操作で確認する。

- 320 / 390 / 1366pxでの複数日プレビュー・変更後の再確認・保存・横幅。
- コメント保存、競合時の入力保持、未保存入力の破棄確認。
- 予定複製、メモタグ、お気に入り、ToDo並び替え。
- 390pxでの前提・関連・リマインダー共通データ反映、完了制限、入力保持。

既存キーボード検査では「完了ボタンが最後」と決めつけず、追加操作を含む最後の有効ボタンからのフォーカス循環を確認する。
Protocol、Origin回帰、PRの認可・Firebaseを含む既存CIを公開判定に使用する。

`tests/origin-advanced.spec.mjs` は繰り返し生成・条件変更、予約、テンプレート、返信、
系列削除の競合、ナレッジ・アーカイブ・受信箱、320pxの表示保存、分類名変更、
開始日保存失敗後の二重作成防止、管理・テンプレートの所有者／競合拒否を確認する。
共同編集専用のリアクション・重複統合は既存Firebase/認可検査も公開判定に含める。
