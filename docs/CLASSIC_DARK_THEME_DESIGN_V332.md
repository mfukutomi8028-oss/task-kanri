# Classic ダークテーマ再設計（Ver.332）

## 目的と原因
利用者から白背景/白文字の組合せ、一覧・カレンダー見出しの眩しさ、担当者名の不可読が報告された。
旧実装は画面単位のライト用CSSに対して局所的な!importantを重ねており、実際の全コンポーネントを覆えていなかった。
特に「担当者バッジ」の背景には白へのグラデーションがハードコードされていた。

## 色の役割（ライトと独立）
- canvas: `--wb-theme-page`。全画面の最も奥の背景
- surface: `--wb-theme-surface`。ページ、ツールバー、モーダルの面
- raised: `--wb-theme-surface-soft`。カード、リスト、カレンダーの日
- inset: surfaceとcanvasの混色。検索・入力欄・選択セグメント
- ink / muted: `--wb-theme-ink` / `--wb-theme-muted`
- line: `--wb-theme-line`
- selected / primary: accentと暗いsurfaceの混色。大きな白ボタンを排除
- semantic: 緊急/期限/完了/削除は上記とは別に意味色を保持
- user badge: ラベル面は暗色＋明るい文字、ユーザー色は輪郭と暗く補正したアイコン面に保持

## 適用
- データ・DOM・タスクのレイアウトは変えない。
- 既存 `color-themes-v329.css` のダーク用ルールを単一セクションへ統合し、旧重複ルールは撤去。
- `html[data-wb-color-mode="dark"][data-wb-color-theme]` の範囲にだけ適用。
- 色選択/保存処理のJavaScriptと8ライト・5ダークの色定義は維持する。
- ToDo、タスク（ボード・一覧・タイムライン）、予定（日・週・月）、業務メモ、統計ダッシュボード、ダイアログ、モバイルを範囲とする。

## 検証基準
1. ユーザー名・カード文字・小さい説明文のコントラストをWCAG 2.2 AA（通常4.5:1）相当で確認。
2. 5ダークテーマで白いコンテナ、白背景/白文字、明るいグラデーションがない。
3. 状態/期限/優先度の意味色を維持し、ライトテーマの computed style を変更しない。
4. 1366pxと390pxでタブ、カレンダー、担当者名、ToDo、ノート、入力欄を確認。
5. タスク保存やFirebase処理を変更せず、既存の各機能の回帰チェックを実施。
