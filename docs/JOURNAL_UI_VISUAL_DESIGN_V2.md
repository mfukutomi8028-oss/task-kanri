# JOURNAL 第2工程：画面ビジュアル設計 v2.0

作成日：2026-11-05
状態：画面イメージ・静的HTMLデザインモック完成／本番実装未着手
対象：Linen（リネン）・Margin（マージン）のPC見開きとスマートフォン単ページ
前工程：docs/JOURNAL_UIUX_DESIGN_V1.md

## 1. コンセプト
JOURNALの2スタイルは同じ業務機能・データを共有し、見た目だけを切替可能にする。

- **Linen**：大人向けの端正な手帳。生成りの紙、青墨の表紙、抑制した装飾、直線基調と明確な余白。
- **Margin**：かわいすぎない遊び心。セージの表紙、くすみテラコッタ／藤色のインデックス、控えめな付箋・色紙、曲線を少し増やす。
- どちらも既存の意味色（期限超過・緊急・状態・固定）を維持。背景色で意味を上書きしない。日本語可読性が優先。

## 2. PCの「今日」見開き
**左ページ**：日付／日付移動、今日の予定件数・未完了ToDo・期限超過、小型時間軸と予定4件、今週の日付導線、「予定を追加」。
**右ページ**：ToDoの完了件数と進捗バー、同じ完了操作を使うToDo一覧5件、進行中タスク2件、業務メモ抜粋。
**外側**：JOURNALロゴ、今日／週間／ToDo／タスク／予定／業務メモのインデックス、検索・お知らせ・新規追加、Linen/Margin切替。

画面内文字は説明可能なUIラベルを使い、意味のない紙テクスチャが可読性を下げないようにする。

## 3. スマートフォンの「今日」単ページ
- **ナビゲーション**：上部にブランド・手帳スタイル切替・お知らせ、下部に今日／週間／ToDo／タスク／メニューを配置。
- **上位情報**：今日の予定、未完了、期限超過をコンパクトに並列表示。
- **予定一覧**：初期表示は2件まで、**「残り2件の予定を見る」**で追加2件を展開。必要な予定全件へのリンクは維持。
- **ToDo**：予定より下に完了数・チェック一覧を置く。実際の縦スクロール初期表示で未完了ToDoにも到達できるように配置。
- **続きの領域**：進行中タスク・業務メモ抜粋。その他ページへの導線は残す。
- **タップ操作**：チェック・予定展開を見た目モック上で試せる。追加／通知／検索／ページ切替は**未接続**であることを明示。

## 4. デザイン上の決定と実装時の注意
1. JOURNAL の日次・週間・一覧・詳細などは既存の保存・購読ownerと連携し、Firebase処理を増やさない。
2. Linen/Marginは同じHTML構造を共有し、CSSトークンと最小限の装飾差分で切替える。
3. モバイル予定の「最初の2件」は表示上の折りたたみであり、予定の取得数・検索対象数を制限しない。
4. ToDo完了表示、期限超過、優先度、通知はClassic/Modern/Palette間で意味・操作・データを揃える。
5. 現行displayセレクタを正本として増設し、新旧切替ロジックの重複を避ける。並行開発中のModern/Palette側の最新版を必ず再調査する。
6. 本番公開する際は、リリースマニフェスト・資産一覧・責務台帳を最新基準に更新。旧資産の互換性を確認し、既存動作を崩さない。
7. この段階の静的HTMLモックはデザイン説明専用。業務データはダミーで、新規追加・検索・各画面の操作などは未接続。実アプリ本体とは独立。
