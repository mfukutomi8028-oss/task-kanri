## 1. 目的と基本原則
Classic・Modern・Paletteと並存する「手帳型」表示 JOURNAL を追加する。JOURNAL内で **Linen**（大人の上質な手帳）と **Margin**（過剰にかわいくない、遊び心のある手帳）を切り替える。

1. 手帳らしさは情報設計・見開き・タブ・ページ導線で実現し、紙テクスチャやアニメーションを主役にしない。
2. タスク・ToDo・スケジュール・業務メモ等の保存/購読/競合制御/通知は既存のcanonical ownerに一元化する。JOURNAL専用のFirebase client/第二のデータ保存経路を新設しない。
3. 既存Classic・Modern・Paletteの挙動を維持し、対象外のCSSや画面処理を変更しない。
4. 新しい表示形式の追加と色テーマの選択は別概念として扱う。状態/期限超過/緊急/固定等の意味色はテーマにより失われない。
5. PC・タブレット・スマートフォン/キーボード操作に対応。空・長文・大量件数・オフライン・競合状態も画面設計に含む。

## 3. 表示体系
表示モード: Classic / Modern / Palette / Journal （Paletteは他チャットで開発中。実際の選択肢・資産名は統合時に再確認）
Journalデザイン: Linen / Margin（画面内のデザイン切替ボタン、設定側にも同じ選択）
保存スコープ: room + userで分離した端末ローカル設定（現行仕様に合わせる）。Firebaseには見た目設定を書き込まない。
状態属性案: html[data-wb-display="journal"][data-wb-journal-theme="linen|margin"]。
適用クラス・属性の設定主導権は既存display selectorに集約。

## 4. 情報アーキテクチャ / 共通ナビゲーション
- **今日**: 左ページ「日付、予定タイムライン、期限/優先・お知らせ」、右ページ「今日のToDo、自分の担当、メモの抜粋」。見出し内に未完了・期限超過・今日の件数を小型サマリで表示。
- **週間手帳**: 左ページ「週の予定、日付別移動」、右ページ「週のタスク・ToDo、優先事項・メモ」。曜日セルから予定の作成、日次ページへ遷移。
- **ToDo**: 左ページ「未完了、並替/絞込、クイック追加」、右ページ「完了履歴/内容と日付」。完了操作は既存canonical handlerへ委譲し今日画面と同一ボタン/状態表示。
- **タスク**: 左ページ「検索・一覧・状態/担当/分類絞込」、右ページ「選択中の詳細・コメント/関連情報への導線」。ボード/一覧/タイムライン/統計は既存機能へ切替導線を用意し同等の機能を欠落させない。
- **予定**: 左ページ「既存予定表示（日/週/月等の現行可能範囲）」、右ページ「選択予定の詳細/関連タスク」。繰返し、複数日コピー、通知、編集・削除は既存ダイアログを利用。
- **業務メモ**: 左ページ「メモ一覧・検索・追加」、右ページ「選択メモの内容をスクロールして表示/編集導線」。共有範囲・保存履歴は現行挙動を維持。
- **お知らせ・通知**: 総合インジケータから現行のお知らせ・通知UIへ移動。既読・返信などの動作は既存owner。
- **その他の既存機能**: ワークフロー、関連付け、テンプレート、複数選択/一括操作、アーカイブ、スター、固定、設定/ユーザーなどは導線を残す。情報密度と操作の再構成のみ。

### タブ・ページ移動
PC: 左側に「今日 / 週 / ToDo / タスク / 予定 / メモ」の目印がある縦インデックス。画面上部には検索・新規追加・通知・切替。
タブレット: 1ページ幅または見開きをビューポートに応じて切替。タブは横スクロール可能。
スマートフォン: 1ページずつ表示。上部にページ名・日付移動・検索・追加。下部ナビ（今日/週/ToDo/タスク/メニュー）、メニューから予定/メモ/設定へ遷移。ページめくりのスワイプは縦スクロールやチェック操作と競合しやすいため **必須操作にしない**。

## 5. 画面レイアウト（実装用）
想定ブレイクポイントは最終的な実機計測で調整：
- desktop >= 1200px: 見開き2ページ、中央の綴じ目、左/右ページそれぞれ独立スクロール領域は原則禁止。全体スクロールを優先し、情報が多い箇所のみ内側スクロール。
- compact 768–1199px: 見開き2ページを維持できる場合は省スペース化。狭い場合は単ページレイアウト（無理な縮小はしない）。
- mobile <= 767px: 単ページ。タップ目標は原則44x44 CSS px以上、ボトムナビを固定しコンテンツに十分な下余白。
- 標準本文 15–16px程度、見出し20–28px、補助情報13–14px程度。小さな数字やメタデータは内容が読めることを優先。
- 検索、並替、追加、チェック完了を視覚的に近接。操作フォームの入力、ダイアログ、ToDo完了操作は全画面で一貫。
- ダイアログを閉じても元のページ・スクロール・選択項目を極力保持。
- 紙の綴じ目/影/罫線はpointer-eventsを持たない装飾として設計。

## 6. JOURNALテーマトークン v1
※ これらは初期デザイン値。実装時に意味色と暗色モードの整合性を実画面でチェックする。

| token | Linen | Margin |
|---|---|---|
| 背景 | #F2EFE9 | #F0F3EE |
| 紙 | #FFFEF9 | #FFFDF6 |
| 本文 | #242B32 | #263633 |
| 補助文字 | #526068 | #56665B |
| アクセント | #2F6170 | #2E6C5F |
| 遊び心アクセント | 原則使用しない | #A64F32、#65568F |
| 装飾 | 繊細な罫線、角丸8px以内 | 付箋/インデックス、角丸12–18px |

上記の本文/補助文字/アクセントと紙色のコントラスト比は、設計値でいずれも5:1以上（WCAG 2.2 AA通常文字4.5:1を超える）。実装時は hover/disabled/選択/ダークモードを別途検査。ダークモードを導入する場合、白い紙をそのまま残すのではなく、暗い紙/文字/罫線を再定義。

### Linen
- スモークブルー、墨、生成り、直線基調。
- ノートの細い罫線は主張しない。過度な手書きフォントは使わない。
- 見開きの余白と整理感で「大人の手帳」を表現。

### Margin
- セージ、テラコッタ、くすみ藤色のインデックス・付箋。
- 意味のない背景色がテーマ色と競合しないよう token化。
- イラスト/シールは装飾領域に限定し、一覧件数や操作の視認性を損なわない。
- ボタンを押せるか分からない「ただの飾り」にならないようアイコン＋テキストを併記。

## 7. 必須の画面状態
- normal: 機能がすべて使える状態
- empty: 予定ゼロ、ToDoゼロ、メモゼロ等で分かりやすい追加導線
- dense: 100件以上や長文でもカード高さを固定しすぎず、一覧密度とスクロールの両立
- overdue: 期限超過はテーマから独立した警告、アイコン・文字でも識別
- loading/offline/syncing/conflict: 読み込み、ローカルのみ、同期中、競合を各画面に一貫表示。成功を装わない。
- completed/archived: 完了履歴・アーカイブ・更新記録が閲覧可能
- keyboard/focus: インデックス/ページ/チェック/ダイアログがキーボード操作可能
- reduced-motion: ページめくり等の動きを抑止しても操作可能
- theme change: Linen ↔ Marginを切替してもページ/検索/選択を保持

## 8. 既存機能との対応・実装順
1. **調査と接続マップ**: 現行 mainのDOM、イベント、保存正本を棚卸し。並行開発の進展を再確認。active manifestと責務台帳を確認。
2. **モード選択統合**: 既存 modern-display-v356.js のセレクタを拡張/置換（その時点で最新版が優先）。Classic/Modern/Palette/Journalを一元管理。新しい並行セレクタは作らない。
3. **共通JOURNAL Shell**: Journal専用デザインで既存画面DOMを必要な箇所に投影しつつ、従来のcanonical write/editイベントを委譲。二重イベント、DOMの複製によるID衝突、古いDOM参照を避ける。
4. **今日→ToDo→タスク→予定→業務メモ**: 操作頻度順に導線を接続。繰返し、通知、一括操作等の既存機能の機能差分表を更新。
5. **2デザイン統合**: Linen/Marginは同一機能コンポーネントにトークンと低コスト装飾差分のみ付与。
6. **表示QA**: PC/スマホ、ライト/将来のダーク、低密度/高密度、長文、絞込、ToDo完了、タスク詳細、予定編集、メモ編集を確認。
7. **統合**: 最新mainへのリベース・CI・GitHub Pagesリリース条件を確認し、既存機能を維持したうえでmainへ統合。リリース番号と資産台帳の一元更新。旧参照を安易に削除しない。

**禁止**: 既存のFirebase/業務ロジック複製、相互依存の新旧モードセレクタ併存、Classic/Modern/PaletteのCSSに無条件で上書きすること、見た目のための新規保存形式導入。

## 9. 受入基準
- Classic/Modern/Palette/JOURNALを切替できる（Paletteが未統合なら先行統合は保留）。Linen/Margin切替でも機能・データは同じ。
- ToDo/タスク/予定/業務メモの新規・編集・削除・既読/履歴等は既存仕様を保持。既存機能への導線が消えない。
- 期限超過・緊急/優先度/固定・通知の区別が背景色だけに依存しない。
- 390px級スマホで横溢れせず、重要ボタンが重ならず、読みやすい。
- 既存で守るべき各種競合制御、再発防止、通知動作、繰返し・まとめ操作が変化しない。
- ブラウザ/データ負荷下でも読みやすく操作できる。テストは現行のProtocol/UI/Firebase系を利用、必要なJournal向け回帰テストを最小限追加。
- 一切のセキュリティ改善を暗黙の既成事実としない。
