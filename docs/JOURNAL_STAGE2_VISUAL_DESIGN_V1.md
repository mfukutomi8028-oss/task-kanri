# JOURNAL 第2工程: Linen / Margin 画面ビジュアル設計 v1.0
作成日: 2026-11-05
状態: 画像モックアップ制作完了 / 実装未着手

## 1. この工程の成果物
- 「Linen」「Margin」の2テーマについて、PC見開きとスマートフォン単ページを扱う比較用ビジュアルデザインを制作。
- ChatGPT会話内の画像モックアップは **視覚的な方向性** の参照。画像上の仮の時刻・件数・用語・装飾を業務ロジックの正本にしない。
- コード実装の正本は本ファイルおよび `docs/JOURNAL_UIUX_DESIGN_V1.md`、既存コードの実仕様とする。
- 他画面のmain/currentブランチの変更はこの工程で行っていない。

## 2. PC（Linen）
- 概念: 洗練された革の手帳と生成りのリフィル。極細の罫線。ブルーグレーの小さなインデックス。
- ヘッダー: 業務管理ボード、JOURNAL、デザイン名、検索、通知、設定、利用者。
- タブ: 今日 / 週間 / ToDo / タスク / 予定 / 業務メモ（選択状態は文字と形状でも表現）。
- 今日ページ: 左側に日付と予定タイムライン、右側にToDoとメモ。概要の未完了・期限超過・今日・自分の担当数は表示できる導線を維持する。
- ページ余白は「上質さ」に寄与するが、100件以上あるときの実用性を優先し可変密度にする。
- 主要ボタン: +予定、+ToDo、+タスク、+メモ、重要項目の詳細閲覧を分かる位置に置く。

## 3. PC（Margin）
- 概念: 大人の手帳に付箋/小さなインデックス/くすみ色を加えたもの。かわいすぎない。
- Linenと完全に同じ情報構造/同じ操作階層/同じ記録データを用いる。
- 日付見出し・注意欄・メモに浅い色のマーカー風背景を使用。装飾（クリップ、植物、カップ等）を業務カードと誤認させない。
- 各タブ色は分類補助。期限超過・緊急などの意味色とは区別する。

## 4. スマートフォン（両テーマ）
- 左右の見開きを縮小しない。1ページずつ読みやすく並べる。
- 原則下部ナビ: 今日 / 週 / ToDo / タスク / その他。その他に予定 / 業務メモ / 設定。選択状態が分かるテキスト・アイコンを併用。
- 上部は現在ページ名、日付前後移動、通知、検索。追加は右下の + から予定・ToDo・タスク・メモを選ぶか文脈追加ボタンを置く。
- 閲覧領域は単一縦スクロール。タブ固定やFABが項目と重ならないよう、safe area + 余白を確保する。
- ページ遷移はボタン操作を必須とし、スワイプに依存しない。
- 予定・ToDo・タスク・業務メモの作成編集は既存canonical ownerへ委譲。

## 5. 画面デザイン向け固定仕様
| 種別 | Linen | Margin |
|---|---|---|
| キャンバス | `#F2EFE9` | `#F0F3EE` |
| 紙 | `#FFFEF9` | `#FFFDF6` |
| 本文 | `#242B32` | `#263633` |
| 補助文字 | `#526068` | `#56665B` |
| メインアクセント | `#2F6170` | `#2E6C5F` |
| 第二アクセント | 抑制 | `#A64F32` / `#65568F` |
| 角丸 | 6–10px | 12–18px |
| 手帳表現 | 控えめな罫線/綴じ目/細いタブ | くすみ色の付箋/太めタブ/装飾を限定 |

表示目安: 本文16px/補助14px/見出し22–28px/タップ領域44px以上。実装時に実機描画で調整。

### カラーモード
- 最初の視覚設計はライトを基準とする。
- 将来的なダーク展開は紙面/タブ/入力部品を専用トークンに再割当し、白背景＋白文字の組合せを起こさない。
- 意味色（期限超過、優先度、固定、警告）を外見テーマで変えない。

## 6. 重要な画面・機能要件（モックアップの省略表示に惑わされない）
- 今日の予定、全体のお知らせ、今日のToDo、業務メモ/タスクへの導線。
- タスク一覧 / ボード / タイムライン / 統計、担当・分類・状態のフィルター、検索・ソート、詳細、コメント、複数選択一括操作。
- ToDoの完了操作のボタン/文言/完了履歴は「今日」と「ToDo」でも統一。
- 予定の登録・編集・削除、関連タスク、繰返し、複数日コピー、通知。
- 業務メモの追加・編集・削除、長文メモを画面上でスクロール閲覧可能。
- 緊急/期限超過/固定などが背景色だけでも判別できるよう文字・アイコン併記。
- Firebaseの正規化、競合制御、既読・リマインダー、削除フロー等の現行仕様に変更なし。

## 7. 実装設計へ引き継ぐ際の注意
- 現行mainは第1工程時点でVer.356。Modern表示切替が `modern-display-v356.js`、Classic色設定が `color-themes-v329.js`。並行開発で変化している可能性があるため第3工程開始時点の最新版を再取得する。
- Modern/Palette/JOURNALの表示切替は「既存選択機構を置換・拡張」し、二重切替・重複listener/保存キーを作らない。
- 同じIDのDOMコピー、二重Firebase購読、独立した書込ロジックを禁じる。
- Journal固有CSSは `html[data-wb-display="journal"]` 配下に限定、Linen/Marginは `data-wb-journal-theme` とCSS variablesで分岐。
- 見開きの中央綴じ目、タブ、イラストをポインター不可の装飾とする。キーボード/スクリーンリーダーの操作順は業務情報を優先。
- 安全上、機密情報・患者情報は現行の認証/アクセス制御が適切に整備されるまで入力しない。
