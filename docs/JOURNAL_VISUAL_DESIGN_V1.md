## 設計の要点

### 共通
- 手帳のページタブに **今日、週間、ToDo、タスク、予定、業務メモ** を配置。6画面の情報設計を想定。
- PCは日程中心の左ページ、ToDo/進行中タスク/業務メモ中心の右ページという見開き。日付ストリップと未完了/期限超過/今日予定の小型統計を表示。
- スマホは390px幅の単ページレイアウト。固定下部ナビ（今日/週間/ToDo/タスク/その他）とし、予定/業務メモは「その他」経由。初期画面では最初の予定2件を示し、残りは「すべて見る」から一覧へ移る。
- 画面デザインの例示日付は**2026年11月5日（木）**。画面上の件数・予定・業務メモは架空のサンプルデータであり実際の本番状況ではない。
- 期限超過は赤系の警告ラベルと文字で区別し、装飾テーマ色とは独立して扱う。
- 入力フォーム・操作処理を追加する段階ではClassicの正本に接続し、二重書込やDOM重複のない設計にする。

### Linen
- 背景 `#F1EFEA`、紙 `#FFFDF8`、インク `#25343C`、アクセント `#315D6E`、ブックカバー濃紺系。
- 細い罫線、余白、落ち着いた明朝英字＋可読性の高い和文。アニメーションや付箋装飾は控える。
- 印象：知的、静か、上質、業務へ集中。

### Margin
- 背景 `#EDF1EB`、紙 `#FFFDF7`、インク `#283B34`、アクセント `#3F7568`、セージ系ブックカバー。
- 色分けしたインデックス、薄いマスキングテープ、点線の件数枠、控えめな手描き風の下線や葉の装飾。アクション領域に装飾が被らないこと。
- 印象：気取らない、親しみやすい、かわいすぎない、明るい。

## 第3工程への引継ぎ

1. **最新mainと並行ブランチの棚卸し**。Modern/Palette側のモード選択に統合し、見た目切替処理を二重化しない。
2. JOURNALの共通画面Shellを実装し、Linen/Marginをデザイントークンとして分離する。デザイン試作HTMLをそのまま本番の重複処理として埋め込まない。
3. 既存のToday/ToDo/タスク/予定/メモのcanonical action・保存経路を再利用する。閲覧/追加/編集/完了/履歴/繰返し/競合制御/一括操作の導線を省略しない。

5. モバイル320/390/430px、PCの一般的な幅、モーダル/長文/大量件数/オフライン状態を軽量な回帰テストで確認する。
6. manifest / 責務台帳 / ページ公開資産は最新プロジェクト規約に沿って一元更新する。実装完了時のみmainへ反映する。
