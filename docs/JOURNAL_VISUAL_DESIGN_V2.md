## 1. 提供するビジュアル
1. Linen / PC 今日ビュー: 1540×950の見開き（左: 週間日付・今日の予定 / 右: 今日のToDo・優先タスク・業務メモ）。
2. Linen / モバイル 今日ビュー: 390×844、単ページ表示、日付移動 + 予定 + 次ページ導線、固定下部ナビ。
3. Margin / PC 今日ビュー: Linenと同一機能構成、セージ色の表紙・リング・付箋・色分けインデックスで軽い遊び心を追加。
4. Margin / モバイル 今日ビュー: 単ページ + 下部ナビ。Margin固有の色は装飾を中心に適用し、警告等の意味色を分離。
5. 追加のモバイルToDoサンプル: 両テーマにおいて完了チェック + 進捗 + 優先タスクを確認可能。
6. 比較シート: 両テーマのPC + スマートフォンを1枚に並べた画像。

画像の業務内容・件数・日付は**仮のサンプルデータ**。2026-11-05(木)のデザイン見本として制作。Firebaseや本番運用データには接続しない。

## 2. レイアウト要件
- PC: ひとつの手帳フレームの内側に2ページ。左ページは**予定・日付**、右ページは**やること・優先事項**。綴じ目は純粋な装飾でクリックを妨げない。
- 上部: JOURNALの識別、機能タブ (今日 / 週間 / ToDo / タスク / 予定 / 業務メモ)、Linen/Margin選択、お知らせ。
- 状態情報: 「未完了」「期限超過」を上部に小さく表示し、期限超過は常に独立した警告色/文言で示す。
- 日付: 1週間の日付帯と日単位の前後移動。現在日を選択状態で示す。
- 予定: 時刻、件名、分類・概要、色付きの細線。PCでもスマホでも文字数が少ない行を優先、長文は省略/詳細導線を検討。
- ToDo: 全表示で**同じチェックボックス設計**。チェック時は行のスタイルと進捗数を同時更新する。
- 優先タスク: 作業名、担当、期限、状態。件数過多でも一覧情報は一行目で把握できる。
- 業務メモ: 長文でも全文/スクロール/編集が可能なページを実装工程で用意する。
- モバイル: 2ページをそのまま縮小しない。390pxで横はみ出しゼロ。1ページ表示にして下部ナビからToDoページへ移動。新規追加ボタンは上部ヘッダーに配置し、本文・下部ナビと重ねない。
- 操作: PCのメニューバーとスマホ下部ナビは現在ページが必ず視覚的に分かること。画面変化しない偽ナビは禁止。

## 3. Linen（大人の手帳）意匠
- 配色: canvas #EDECE8 / paper #FFFEF9 / ink #252F37 / accent #355E72 / muted #596873
- タイトル: 日本語セリフ系、上品で読みやすい太さ。本文: Noto Sans CJK JP相当。
- 見開き: 静かなグレー系表紙、細い線、余白、控えめな紙の陰影。付箋を多用しない。
- 日付: 大きめの数字と明確な曜日表示。支援文は日本語を併記。
- イメージ: 静か・知的・実務向け。余白を過剰に取らず、見開き内に予定とToDoが収まるようにする。

## 4. Margin（少し遊び心のある手帳）意匠
- 配色: canvas #EAF0E9 / paper #FFFDF7 / ink #293D38 / accent #356C5F
- 装飾: セージグリーンの表紙、リング綴じ、薄いマスキングテープ、小さなインデックス、メモの付箋色。
- 見出し: サンセリフ太字。Linenより少し柔らかく、でも読みやすさ/情報密度は共通。
- 付箋/装飾は操作と衝突しない。意味色（危険・期限超過・完了・固定・優先度）と、見た目だけの装飾色を分離。
- 読みやすさのため、明るい背景に白字を置くようなコントラスト不良を禁止。

## 5. PC / モバイル状態の扱い
- desktop（目安1200px以上）: 対称の見開き2ページ。
- compact（768～1199px）: 見開きの最低可読幅を確保できるときだけ継続。不可能なら単ページへ切り替える。ブレイクポイントは実装後に計測で確定。
- mobile（767px以下）: 単ページ、ナビは下部固定、追加ボタンは操作と重ならない配置。タップ領域は原則44×44px以上。
- 完了・期限超過・オフライン・競合・空状態・大量件数・長文・キーボードフォーカス・リデュースモーションは実装時の必須検証状態。

## 6. モックアップで動作確認した範囲
- 手帳テーマ Linen ↔ Margin の切替
- PCと390pxスマホの表示（水平はみ出しゼロ）

## 7. 実装時の推奨構成
既存の `modern-display-v356.js` はClassic DOM共用のpresentation-onlyモード選択実装だった。これを**現行mainの最新版を読んで**更新/統合し、Classic / Modern / Palette / Journal の選択肢を1つの正本で管理する。同名のモード・色切替を別スクリプトで重複させない。

- JOURNAL内のテーマは `linen` / `margin` で1つの共通業務UI。CSSトークン中心で切替、同じイベントと保存処理を共有。
- canonical data/write ownersは `app.js` / `todo-sync-v136.js` / `workspace-write-v538.js` / `workspace-memo-v539.js` 等の**当時の最新版**。新規Firebase client、同機能の二重イベント、保存経路の複製は禁止。
- 既存DOMを無造作にクローンしてID衝突やダイアログ動作の破綻を起こさない。必要なUI投影/再利用の境界を調査してから実装。
- 画面固有のCSSは必ずJOURNAL表示属性にスコープしClassic・Modern・Paletteのスタイルに漏らさない。
- main直変更でなく専用のfeatureブランチで実装、最新mainとの差分確認と回帰検証後に統合する。
- release-manifest.js / patch-responsibilities.json / CI / Pagesの更新を既存規約で一元管理する。
- 医療情報や患者情報等を安全に扱えるという前提にしない。アプリREADMEに記載のセキュリティ制限は引き続き適用。
