# JOURNAL 機能・表示の対応表

2026-11-12 / Ver.574

JOURNALは確定済みの手帳デザインを維持する。表示構成は専用にし、保存・同期・権限・競合判定は共通の正本を使う。原本の操作部品を移動する場合はID・イベントを保持し、画面モード終了時に元へ戻す。

## 実装上の境界

- `WorkBoardJournalNavigation` は案件を開くだけの境界。検索条件の解除やデータ書込を行わない。
- 記録棚は共通snapshotとworkflow更新通知を利用し、Firebaseクライアント・業務データの独自キャッシュを作らない。
- ナレッジの編集中は背景更新でフォームを再生成しない。保存時は開始時のrevision・ルーム・利用者を送る。利用者変更時は表示と未保存入力を閉じる。
- 詳細の共通タブバーは直下に保持する。コメント・関連設定の拡張がこの境界を参照するため移動しない。本文パネルのみ1つの記録ページへ移す。
- 詳細の監視は詳細本体・記録ページ・関連設定の直下childListに限定する。入力・属性変更のたびに全体を監視・再生成しない。
- 予約ページは表示済みの実カードを日付別に配置するだけ。開始日の保存先と保存ボタンの処理を追加しない。

- 予定コピー・系列削除・日付移動は原本を見開き用紙へ配置し、共有更新は独立した閲覧用紙へ移す。閉じた後の画面切替でも元の配置・見出しを復元する。
- 記録棚から開いた案件ノートは、元のページを維持したまま保存後に共通の描画処理で更新する。

## 検証対象

`tests/journal-display-v367.spec.mjs` に既存の主要ページ・保存後復帰に加え、記録棚、利用者切替、未保存確認、ナレッジ競合、開始日変更、詳細コメント・関連設定の保存、予定コピー、系列削除、日付移動、共有更新、Classicへの構造復元を収録する。共通の認可・Firebase Emulator・ブラウザ回帰は必須検査として維持する。
